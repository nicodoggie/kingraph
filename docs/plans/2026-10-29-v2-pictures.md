## Approved design and compatibility

The source-relative asset boundary is Vite for Astro/Vite projects, not the viewer. Resource declarations belong in versioned family data; resource loading and output policy belong in environment adapters. Generated inline SVG may link images. Portable SVG/PNG export embeds them. Generation location and embedding policy are independent.

- Explicit `schemaVersion: 2` adds `pictures`, a mapping of IDs to exactly one nonempty `url`, `data` or `path` source. Picture-source objects reject ambiguous/unknown fields. `url` is absolute HTTP(S); `data` is a complete base64 PNG/JPEG data URL; `path` is a relative source path (parent-directory references permitted, not absolute paths or URI schemes). Keep the existing family/person/style fields and extension metadata semantics; only v2 picture references gain catalog meaning.
- Every present nonempty v2 person picture must name a declared entry. Reject missing references with person/key context before loading. Load only referenced entries, once per key per render. Keep unused valid declarations free of I/O.
- Missing versions still mean v1. V1's `picture` string, passthrough metadata, explicit `pictureResolver`, DOT behavior and return types stay intact. Root APIs dispatch explicitly; `/v1` and `/v1/schemas` remain v1-specific, including browser conditions. Add `/v2` and `/v2/schemas` with an explicit v2 API and meaningful inferred types. Unsupported versions are rejected, not guessed from fields.
- Reuse one canonical graph builder. Preserve the original person/tree metadata seen by date/age adapters; do not mutate authored data. Pure v2 DOT substitutes catalog source strings without loading resources; relative path strings remain document-relative for native callers. V1 DOT remains unchanged.

## Frozen cross-leaf API

- `src/v2/schemas.ts` exports `PictureSourceSchema`, inferred `PictureSource`, v2 `FamilyTreeSchema`/validation and appropriate public inferred types.
- `src/pictures.ts` retains legacy `ResolvedPicture {dataUrl,width,height}` and `PictureResolver`. Add `PictureMode = 'embed' | 'link'`, `ResolvedPictureAsset {href:string,width:number,height:number}`, `PictureLoadContext {id:string, documentUrl?:string, mode:PictureMode}` and `PictureLoader = (source: PictureSource, context: PictureLoadContext) => ResolvedPictureAsset | Promise<ResolvedPictureAsset>`.
- Shared render options add optional `pictureMode`, `documentUrl` (an absolute source-document/base URL), and `pictureLoader`. Validate original options before composition. Types for explicit v1/v2 entries must not silently advertise unsupported document versions; retain existing usable callback contracts.
- The environment default loader is passed into shared preparation. `pictureLoader` is an explicit override for v2 access policy; legacy v1 `pictureResolver` is unaffected. A loaded href can be a supported image data URL or a resolved HTTP(S)/file URL as appropriate to the adapter; internally Vite may register a deterministic asset placeholder awaiting native public-URL binding. Browsers do not gain local filesystem access from a file URL. Positive finite dimensions are required. Register actual hrefs/sizes with Viz, preserving native image generation.
- Node `src/node_pictures.ts` exports `loadPictureAsset(source, context)`. Browser `src/browser_pictures.ts` exports its counterpart `loadPictureAsset`, alongside unchanged `loadPicture(source)` convenience. Expose these through their corresponding public root/browser/v2 entries.
- Node defaults to embedded SVG. Browser defaults v2 SVG to linked output. All PNG/PNG-image rendering forces embedded preparation. Explicit `pictureMode` controls SVG policy. CLI exports default embedded. Vite v2 raw imports default linked for inline use; URL/data-URL SVG imports default embedded because SVG image contexts cannot load nested external images. Explicit plugin options may override SVG policy.
- Browser-only `embedSvgPictures(svg)` returns a portable SVG from an already generated linked SVG, resolving/deduplicating image hrefs with native loading, preserving layout and failing clearly on CORS/decode errors. It does not rerun Graphviz. Keep DOM use inside functions and preserve SSR-safe imports.
